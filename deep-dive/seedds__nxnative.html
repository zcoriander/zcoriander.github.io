seedds/nxnative

https://github.com/seedds/nxnative ★ 13.1k Python

把 Switch 游戏转成能在 iPhone/iPad/Mac 上原生运行的 IPA。不是模拟器，而是把 NSP 文件夹重写成未签名 IPA，游戏代码直接跑在 Apple 芯片上，图形层用 Metal 重建。仓库里不含任何游戏内容，只提供转换和运行框架。

它到底在做什么

nxnative 的核心是三层：NSO rewriter 把 Switch 的 NSO 可执行文件转成可在 Apple 平台运行的代码；Horizon HLE host 在高层模拟 Switch 系统服务，让游戏认为自己还在原生主机上；NVN→Metal 把 Switch 的图形 API 指令重写成 Metal，跑在 A17 Pro 及以上芯片上。

关键区别是「原生运行」而不是「模拟器」——没有整机模拟层，游戏自己的代码直接在 Apple 芯片上执行，性能损失理论上更小。但代价是你需要自备合法的 Switch 游戏 NSP 文件，仓库本身不包含任何游戏内容。

  • NSP 文件夹 → 未签名 IPA，可侧载到 iPhone/iPad/Mac
  • NSO rewriter + Horizon HLE host + NVN→Metal 三层重建
  • 游戏代码直接在 Apple 芯片上运行，非整机模拟
  • MIT 许可证，仓库不含游戏内容，需自带合法 NSP

安装和使用门槛

这是一个 Python 项目，但「能跑起来」不等于「能玩起来」。你需要：一台 A17 Pro 以上的设备（iPhone 15 Pro 系列、M 系列 Mac 或新款 iPad）、合法的 Switch 游戏 NSP 文件、愿意折腾侧载（sideload）的心理准备。

目前 735 个未关闭 issue 说明兼容性和稳定性还在早期阶段，不是随便下载就能开玩的成品工具，更适合当作技术预览或学习对象。

  • 设备门槛：A17 Pro / M 系列芯片以上
  • 需自备合法 Switch 游戏 NSP
  • 需接受侧载和未签名 IPA 的信任风险
  • 735 个 open issue，早期项目，稳定性未知

为什么这个方向有意思

它走的是「游戏代码原生化」而非「主机整机模拟」的技术路径，这在 Switch 游戏上相对少见。如果 NVN→Metal 这层图形重建能稳定下来，对其他跨平台游戏移植也是有参考价值的。

同时它也提醒我：开源项目里「原生运行」和「模拟器」的边界正在模糊，未来可能有更多「把 A 平台游戏变成 B 平台 IPA/APK」的转换层项目出现。

我的结论

如果你有合法的 Switch 游戏、一台 A17 Pro 以上的设备、又愿意折腾，这是目前最值得关注的「Switch 游戏在 Apple 设备上原生跑」的开源项目之一。但别把它当成成品游戏机——735 个 open issue 提醒你，这更像是一个技术预览，适合当学习对象或偶尔尝鲜，不适合当日常娱乐工具。
